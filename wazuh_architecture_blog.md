# Demystifying Wazuh Architecture: A Deep Dive into Open-Source SIEM and XDR

Modern enterprise security demands continuous visibility, rapid threat detection, and automated response capabilities. Enter **Wazuh**—a powerful, open-source security platform that unifies Security Information and Event Management (SIEM) and Extended Detection and Response (XDR) capabilities. 

Whether you are securing a small lab or a massive multi-cloud enterprise infrastructure, understanding Wazuh's underlying architecture is essential for successful deployment, scaling, and maintenance.

---

## Core Components of Wazuh Architecture

Wazuh relies on a modular, multi-tier architecture designed to separate data collection, analysis, storage, and visualization.

### 1. The Wazuh Agent
Installed on endpoints (such as Linux, Windows, macOS, or cloud instances), the lightweight **Wazuh Agent** acts as the frontline data collector. It runs locally to provide:
* **Log Data Collection:** Reads system and application logs, utilizing event filters and multi-line parsing.
* **File Integrity Monitoring (FIM):** Tracks real-time changes to critical system files, permissions, and hashes.
* **Security Configuration Assessment (SCA):** Scans systems against security hardening benchmarks (e.g., CIS benchmarks).
* **Vulnerability & Inventory Detection:** Identifies installed software packages, open ports, and vulnerable applications.
* **Active Response:** Executes automated countermeasures, such as blocking malicious IP addresses or terminating unauthorized processes.

### 2. The Wazuh Server (Manager)
The **Wazuh Server** is the core processing engine. It receives data streams from endpoints, authenticates agent communication, and processes logs. Its responsibilities include:
* **Parsing and Decoding:** Standardizes raw logs into structured data fields.
* **Rule Matching and Analysis Engine:** Evaluates events against built-in rules to detect anomalies, intrusions, and indicators of compromise (IOCs).
* **Threat Enrichment:** Cross-references telemetry data with threat intelligence feeds and frameworks like MITRE ATT&CK.

### 3. The Wazuh Indexer
Powered by OpenSearch, the **Wazuh Indexer** is a highly scalable, full-text search and analytics engine. It securely stores, indexes, and manages security alerts generated by the Wazuh server, providing fast full-text searching and horizontal clustering for heavy data loads.

### 4. The Wazuh Dashboard
The **Wazuh Dashboard** is a web-based user interface built on OpenSearch Dashboards. It delivers interactive data visualization, real-time alert monitoring, regulatory compliance reporting (PCI DSS, GDPR, HIPAA, NIST), and direct configuration management for agents and servers.

## Communication Flow and Protocols

Data flows securely across the Wazuh ecosystem via encrypted channels:
* **Agent to Server:** Endpoints communicate securely with the Wazuh server using AES encryption (128/256-bit keys).
* **Server to Indexer:** **Filebeat** runs locally on the Wazuh server to securely stream alerts and log data to the Wazuh indexer over TLS.
* **Dashboard to Server/Indexer:** The web dashboard utilizes secure HTTPS to query the Wazuh Indexer REST API and communicates management controls via the Wazuh Server RESTful API (`TCP port 55000`).

## Deployment Topologies

Depending on your organization's event throughput, infrastructure size, and fault-tolerance requirements, Wazuh supports three main deployment models:

1. **All-in-One Deployment:** All central components (Server, Indexer, and Dashboard) reside on a single host. Ideal for testing, home labs, and small-scale setups.
2. **Single-Node Deployment:** Components are separated across individual dedicated servers, offering cleaner workload isolation for medium environments.
3. **Distributed Multi-Node Deployment:** Features clustered Wazuh servers and clustered indexers behind load balancers. This configuration delivers horizontal scalability, fault tolerance, and high availability for enterprise networks.
